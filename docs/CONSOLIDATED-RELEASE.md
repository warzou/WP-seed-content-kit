## Final tests

- PHP 7.0.33 and 8.4.23: lint and 51 standalone harnesses each. Twelve JavaScript checks passed. See enclosed test records.
- Native WordPress Plugin Upgrader installed official 0.8.1 and upgraded to RC2 in disposable WordPress 7.1.5 / MariaDB 10.11.20 / PHP 8.4. Posts, postmeta and taxonomy table fingerprints and explicit module options exactly match across upgrade. The installed 253 files are byte-identical to the installable manifest. SVG upload permission stays disabled. PHP 7.0 coverage is from the standalone suite and lint, not the same WordPress boot.
- Original L3/L4 reproduced on both versions and with both SQLite and MariaDB. With the same corrected harnesses, L3 passes 144/144 for official and RC2. The missing fixture was a configurable Website registry type, not a product defect. L4's versioned schema and placeholder checks were brought up to the already released contract without removing the collection behavior checks. L4 still demonstrates the old defect on 0.8.1 (18 failed assertions, including two legacy social cards forced to draft). The RC2 legacy normalizer applies the existing HTTP(S) contract to those keys, so L4 passes 87/87. Wrong schemes remain rejected. WordPress Directory new person, L2 and roles pass 35/35, 35/35 and 87/87.
- Formation transactional test: 87 checks. Concurrent test: 14 checks. Separate DB connections overlapped, the second query was observed inside `GET_LOCK` with the first still holding it, exact simultaneous writes produced one row and a duplicate error, distinct writes both saved, self-update passed, conflicting edit failed, and the lock was free after success and error. No locking code change was needed.
- Browser: 66 visible synthetic images loaded across both admin lists on RC1, with no overflow. Before, the Directory table overflowed at widths up to 24000px. Envelopes are 48px / 60px / 150px. RC2 preserves all thumbnail implementation bytes, passes the current thumbnail harness, and serves the admin fixture images and CSS over authenticated HTTP on the new lab. The screenshots are the carried-forward RC1 visual evidence. All 33 original fixture files matched their hashes.
- Measured `currentSrc` and Resource Timing in both lists. The native WordPress responsive JPEG/PNG examples chose compatible 150x300 and 300x100 derivatives (2,834 and 752 transferred bytes, respectively, including overhead). Large JPEG/PNG/WebP without compatible native intermediates still used their originals (389,646 / 80,313 / 44,148 transferred bytes). No custom thumbnail generation, crop, MIME or upload permission change.
- Live functional scope is confirmed by the exact match with the historically validated source and the separately tested RC2 differences. No new integration, product ZIP rebuild, deployment, production change or Git publication was needed after the comparison.

## Human Pass protocol

Use the isolated RC2 lab at `http://127.0.0.1:8879/` on the host, or install the reviewed ZIP in another disposable WordPress. Verify the installable SHA against `SHA256SUMS.txt`. In Directory and Testimonials, compare the SVG portrait/landscape, JPEG, PNG, WebP and no-photo examples. In Directory, start a synthetic person and check the suggested position, optional Country and absence of the former Summary field. Open the example with a native More marker and inspect the introduction/continuation. On the Formation example page, check that one theme appears on two clearly separate dates. Automated upgrade, duplicate refusal, locking, syntax and provider checks do not need to be repeated by the reviewer. No production installation, publishing, commit, push, tag or release is implied by this review.
